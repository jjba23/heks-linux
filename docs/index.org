like, and the seven lines that install it. These pages are everything after
that. Each one owns a subject and is written to be read alone — no page assumes
you have read its neighbour — so the table below is a map rather than a reading
order, and the three routes under it are the orders that do exist.

** Three reading orders

*The first hour.* Read [[file:installation.org][Installation]]'s quick start,
run the seven lines, then keep [[file:commands.org][The command deck]] open
beside the machine. When a chord surprises you,
[[file:keybindings.org][Keybindings]] is the table it came from. Do not read the
rest first: the manual is long, and the desktop is faster to understand by
using it.

*I want to change something.* Start with
[[file:configuration.org][Configuration and customization]] — the parameters
table tells you which name controls what — then
[[file:how-it-works.org][How Heks works]] for the override file and the write
path, then the page that owns the surface you are changing
([[file:desktop.org][the desktop]], [[file:kitty.org][Kitty]],
[[file:zen-browser.org][Zen]]). A palette change has its own route:
[[file:palettes.org][Palettes]], then [[file:desktop.org][the runtime
switch]].

*I want to contribute.* [[file:../HACKING.org][HACKING.org]] first — it is the
tour of the source layout — then [[file:how-it-works.org][How Heks works]] so
the modules make sense, then [[file:philosophy.org][Philosophy]] for the four
ideas a patch is judged against, and
[[file:contributing.org][Contributing]] for the workflow. The
[[file:surfaces.org][surface manifest]] is the fastest way to see what the tree
already covers.

** How these pages are checked

The manual is a directory of Org pages, and a page rots in ways nobody reads a
diff for: a link to a file that was renamed, a page no table grows an entry for,
a command that no longer exists. Each of those is mechanical, so each of them is
a test in ~test/veritas/unit/docs-spec.scm~, run by ~maak test~:

- every page starts with its own =#+title:= and leaves the table of contents out
  (the README has one, the pages are short enough not to need one);
- every page leads back here, to the README;
- every =file:= link points at a file that is there, checked across the README,
  ~HACKING.org~ and every page in this directory;
- every page is reachable from the README, so nothing is written for its author
  alone;
- every task a page names in code markup is a task ~maak.scm~ actually defines;
- and no page names an init system or a package manager this tree does not run
  on. That one is not a style rule: Void is the path, and a paragraph that sends
  a reader to another machine's tooling is a paragraph that does not work.

The surface manifest is the exception to every rule about hand-written pages:
[[file:surfaces.org][it is generated]] by ~maak surfaces~ from the modules
themselves, so it cannot drift from what the tree does.
