* Default Niri keybindings

These are the bindings most people reach for first, and they are not a separate
list: every chord in this page comes from the same two tables the compositors are
rendered from - ~niri-bindings~ and ~labwc-bindings~ - joined against the surface
manifest, which is what says which surface each command reaches. ~heks-surfaces
--keys~ prints the whole table, and ~maak surfaces~ prints the manifest it comes
from. ~Mod+?~ opens Niri's own hotkey cheatsheet in the session. ~Mod+Shift+?~ opens heks-toon instead: Niri, Kitty, Emacs, the shell and
the bar, one page each.  The reference opens with a legend for its own notation -
~s~ is Super, which is Command on this desktop, ~C~ is Control, ~M~ is Alt, ~S~
is Shift - because a cheat sheet written in a notation it never explains is only
useful to its author.

** When a chord does nothing

Three different reasons, in the order worth checking:

- *The table changed and this page did not.* This page is a view of the binding
  tables, and ~heks-surfaces --keys~ prints the same table the compositor was
  rendered from. If the two disagree, the page is the one that is wrong.
- *The focused program claimed the chord first.* A key a program has claimed
  never reaches the compositor. Kitty claims no bare Emacs chord for exactly this
  reason and puts its own commands behind a prefix instead —
  [[file:kitty.org][Kitty]] explains the layer.
- *Nothing is bound to it at all.* ~maak doctor~ prints a line for every surface
  no keybinding reaches, so a feature that is installed and unreachable is named
  rather than guessed at.

Adding a binding is an edit to the ~niri-bindings~ list, and
[[file:configuration.org][Configuration and customization]] says where.

* The LabWC session's own chords

The floating session renders ~labwc-bindings~, and it carries Niri's chords
where the action means the same thing there - ~W-t~, ~W-S-s~, ~W-l~, ~W-C-w~,
the transport keys, the capture verbs.  These are the ones only it has, because
a stacking compositor has verbs a tiling one does not:

| *Key*                          | *Action*                                     |
|--------------------------------+----------------------------------------------|
| ~W-1~ … ~W-4~                  | Go to that desktop                           |
| ~W-Shift+1~ … ~W-Shift+4~      | Take the focused window to that desktop      |
| ~W-Left/Right/Up/Down~         | Snap the window to that edge                 |
| ~W-f~                          | Maximise the focused window                  |
| ~Alt+F4~                       | Close the focused window                     |
| ~W-Shift+/~                    | Open the keyboard reference in heks-toon     |
| ~W-Shift+b~                    | Shuffle the wallpaper                        |

The bar along the bottom is the shell's Windows XP preset: ~WHELK_PRESET=xp~ in
=~/.config/labwc/environment=, written by ~labwc-whelk-preset~.  It is the only
shell this session starts - no dock - and its task buttons are blank for now:
whelk reads niri, sway, Hyprland and X11 window lists, and labwc's is not one it
reads yet.
